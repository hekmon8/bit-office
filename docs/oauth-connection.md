# OAuth connection and metadata outages

Use the configured private MCP endpoint, currently `https://agents.hekmon.com/mcp/oauth`. A successful `/health` or discovery GET does not prove that ChatGPT can complete authorization.

For Client ID Metadata Documents (CIMD), the authorization server must retrieve and validate the client's public HTTPS document. If the pinned SDK reports an upstream HTTP403,429 or5xx, `/oauth/authorize` returns503 with `client_metadata_unavailable` and a fixed explanatory message. On the initial authorization GET, it issues no consent cookie, code, grant or redirect for that failure. Missing documents, invalid metadata, disallowed callbacks, incorrect resources and invalid PKCE remain rejected. This error classification does not restore upstream access; do not use a proxy, stale metadata or a hard-coded client to turn the refusal into consent.

The server already supports dynamic client registration (DCR) alongside CIMD. [OpenAI documents choosing DCR when both methods are available](https://developers.openai.com/plugins/build/auth). Where that selector is available in the connection's management screen, use DCR instead of CIMD. If it is absent, report the missing selector rather than guessing a UI action or disabling server metadata support. Keep the exact callback shown by ChatGPT; do not substitute an older test callback or a wildcard.

DCR registers an OAuth client at the existing `/oauth/register` endpoint. ChatGPT sends the client name, exact redirect URI, grant types, response types and a supported token authentication method; the OAuth provider stores the client registration in the existing `OAUTH_KV`. The authorization request must still pass exact redirect and resource checks and S256 PKCE. The operator then enters the existing management credential directly on this site's consent form and approves `office:manage`. This persists a grant and allows reading and modifying Agent/task records; it does not launch an Agent process. Creating the real client and persistent grant requires the owner's explicit approval. Never retrieve or paste the management credential into logs or chat, and never create a client on the owner's behalf without that approval.

Local tests use the real SDK with disposable in-memory stores and synthetic credentials. They prove the DCR protocol still works when a mock metadata upstream returns403; they do not prove that a real ChatGPT connection, production login, personal-office read or write succeeded. Record the deployed SHA/version and separately verify the real connection after the owner completes consent.

The Demo/private-instance work remains separate. This change neither activates the private viewer nor creates the public Demo Worker, changes credentials, changes bindings, migrates Office data or alters the advertised registration methods.
